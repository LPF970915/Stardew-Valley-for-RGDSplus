# RGDSplus 世界降分辨率与 RGA 实验

日期：2026-10-12。发布构建：`20261012-01`。

## 采用的实现

正式入口设置 `SDV_WORLD_RENDER_SCALE=0.625`。只缩小世界渲染目标；
游戏摄像机、对象坐标、视野、UI、触控和最终 `2048x768` 物理缓冲不变。
100% 游戏缩放的连续双屏世界从 `1024x1536` 变为 `640x960`，
与建议的 `1280x480` 像素数相同。副屏页面模式世界从 `1024x768` 变为 `640x480`。
GPU 将世界纹理放大并拼回双屏；像素细节有所损失。

只降低分辨率会触发当前显示链路更长的客户端交换等待。因此低分辨率路径
同时设置当前游戏 GL 上下文的 `SDL_GL_SetSwapInterval(0)`。
系统 Weston 仍负责物理输出，未更改固件、GPU/CPU 频率策略或系统显示模式。
设置失败自动回退原分辨率。`SDV_WORLD_RENDER_SCALE=1` 重新启动可回退整个路径。
长时间撕裂、延迟和整场游戏覆盖尚未验收，不能据短测承诺全程恒定 30 帧。

证据根目录：`build/performance-rga-20261012/`。使用正式入口、内存农场、中文 UI 150%、
游戏缩放 100%、自动工具动作；采样窗口内不抓屏，结束后抓取两块实体屏。
结果检查 `activeFrames == frames`；没有读取或保存真实农场。帧率为进程绘制帧率，
不是高速相机测得的实体屏独立帧率。温度约 67–71°C，未做温度恒定控制。

## RGA 为什么暂未采用

`tools/rga-probe/rga-bench.c` 在设备 DMA 缓冲上执行 300 帧（先预热 10 帧）并验证输出像素：
`1280x480 → 2048x768` 平均 4.1122 ms、P95 4.6651 ms；
`640x960 → 1024x1536` 平均 4.1318 ms。

真正接入游戏的 `rga-egl.c` 原型使用 EGLImage/DMA 共享，无 CPU 像素读回。
当前同步链路仍需 GPU 完成、RGA 完成和 GPU 再消费纹理，端到端砍树结果比 GPU 放大慢。
单独 RGA 缩放耗时不能替代整条游戏链路测试。

首次原型受 gl4es 延迟绑定影响，曾出现错误纹理；修复为强制实现实际原生纹理绑定后，
`rga-layout-v2-*` 两屏截图才正常。只有 `rga-v2-axe` 用于上表。
异步多缓冲/fence 路径尚未实现验收，不能据此断言 RGA 在所有接法中都无收益。
发布包不含 RGA 原型或测试模组。

## 首次动作长帧

`production-axe-cold-frames.csv` 最长帧 580.29 ms 中，JIT 增量 458.56 ms/53 个方法；
有效采矿最长帧 493.01 ms 中，JIT 增量 390.15 ms/43 个方法。
因此这部分长帧不能通过减少像素数解决。也不能把剩余时间全部归因为磁盘或 GC。

已测试完整游戏 ReadyToRun 候选：确认设备实际映射候选 DLL 后，首次砍树最长帧缩短到
188.19 ms，20 秒平均 39.47 FPS，仍有明显长帧；未加入正式运行时。
保持当前与 Harmony 验证过的运行时配置，不启用未经兼容验证的 tiered compilation。

另一个 QA 实验沿工具动作调用链预编译 1035 个方法，耗时 3.71 秒、无方法编译错误。
之后首次砍树最长帧降到 268.52 ms，但仍有 211.63 ms 长帧及剩余 JIT；
平均 46.48 FPS。证据为 `transitive-precompile-axe*`。该结果尚不能解决首帧目标，
又增加启动期编译与代码驻留成本，因此没有把这个广泛预编译实验加入正式版。

## 作废数据与测试修正

- 早期采矿测试错误使用 `Object(Vector2, string, bool)`，该重载创建大型制作物，
  把石块 ID 343 变成了不存在的 `(BC)343`。错误图标反复分配导致约 20 MB/s 分配率。
  所有文件名含 `pickaxe` 且不含 `valid` 的旧采矿性能数据均作废，不能用于正常采矿结论。
  已改为 `ItemRegistry.Create("(O)343")`，验证其为非错误、非大型制作物、可敲碎石块。
- `r2r-gpu-*`、早期 `r2r-pickaxe-*` 未真正加载 R2R 候选；不用于 R2R 结论。
- `rga-layout`、`rga-nosync-*` 修复纹理绑定前的图像/时序作废。
- UI 测试只改 `baseZoomLevel` 会被目标缩放值恢复；已同时设置 `desiredBaseZoomLevel`。
  修复后的 `production-layout.json` 25 项验收全部通过。
