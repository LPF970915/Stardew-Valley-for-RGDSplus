# ARM64 局域网 LZ4 依赖修复

日期：2026-10-09。范围：补齐原生压缩库，不修改游戏协议、启动器、游戏 DLL、双屏模组 DLL 或存档。

## 原因

掌机加入 PC 主机后，`LidgrenClient` 已收到网络消息，但在
`LZ4NetCompression.TryDecompressStream` 中抛出
`DllNotFoundException: liblwjgl_lz4`，因此界面停在“正在连接”。
这次错误发生在数据接收后的解压阶段，不能把它归为防火墙或 Wi-Fi 不通。

游戏 `LWJGL.LZ4` 使用 Cdecl 调用三个原生符号，JNI 的 `env`、`clazz`
参数均传空指针，缓冲区直接通过 P/Invoke 传入。修复只封装这三个接口，
不是完整的 LWJGL/JNI 实现，也不需要 Java：

```text
Java_org_lwjgl_util_lz4_LZ4_LZ4_1compressBound
Java_org_lwjgl_util_lz4_LZ4_nLZ4_1compress_1default
Java_org_lwjgl_util_lz4_LZ4_nLZ4_1decompress_1safe
```

使用官方 LZ4 v1.10.0 的 `lib/lz4.c`、`lib/lz4.h`，静态编入该共享库。
来源为 `https://github.com/lz4/lz4/tree/v1.10.0/lib`。
构建脚本固定版本并校验下载内容的 SHA256；BSD-2-Clause 许可证随包保留。
不依赖设备另行安装 `liblz4.so`，也不改变游戏的 9 字节压缩消息头。

## 已验证范围

- 主机原生封装：13 组压缩块回环、已知标准块、容量不足/截断输入检查。
- 主机系统的独立 LZ4 库与封装双向解码兼容。
- 设备原生封装：相同的 13 组回环和异常输入检查通过。
- PC 原版游戏程序集和设备实际游戏程序集各 8 组压缩字节/网络流回环通过。
- PC 原版生成的可压缩/随机数据，两组均由设备游戏程序集正确解压。
- 设备生成的可压缩/随机数据，两组均由 PC 原版游戏程序集正确解压。
- 安装后的正式 `LD_LIBRARY_PATH` 可解析 `liblwjgl_lz4`。
- 部署前后，设备入口、内部启动器、游戏 DLL、双屏模组 DLL 哈希保持一致。
- 全程没有终止、启动游戏，也没有读取或写入真实农场存档。
- 重复构建得到相同 SHA256。
- 使用现有干净包脚本 `-SkipBuild` 验证打包：库和许可证均入包，
  286 个文件哈希、运行权限与无游戏资源/存档检查通过。

设备证据：`build/native-lz4/device-20261009-001515/results.json`。
PC 反向验证输出：`PASS: verify, two cross-device game-format fixtures.`
打包检查产物：`build/native-lz4/package/stardew-rgdsplus-dualscreen-0.6.0-reference-v2-clean.tar.gz`。
该包只用于确认现有打包流程包含依赖，未重新编译或部署其中的双屏模组。

三个现有打包脚本都已复制 `libs.aarch64` 和 `licenses`，无需改启动器或
包目录清单；启动器已有正确的 `LD_LIBRARY_PATH`。
库位于 `libs.aarch64`，不会被启动补丁器清理 Windows `gamedata/liblwjgl_lz4.dll`
的步骤误删除。只复制 Windows DLL 或把通用 `liblz4.so` 改名均不能替代本封装。

## 2026-10-09 联机闪退修复

首次补库后实测加入 PC 房间，掌机已经能读到房间并收到联机数据，
但进入农场时黑屏退出。设备日志没有新的 LZ4 错误，也没有 OOM/内核
终止记录；实际异常为：

```text
NullReferenceException
TitleMenu.setUpIcons()
CharacterCreationLayout.AfterSubMenu()
Client.setUpGame()
```

原因是 `TitleMenu.Dispose` 先把 `menuContent` 置空，再通过 `subMenu`
setter 清理子菜单。原布局 postfix 在释放期间再次调用
`gameWindowSizeChanged`，导致 `setUpIcons()` 使用已释放的内容管理器。
`CharacterCreationLayout.AfterSubMenu` 现在在 `title.menuContent == null`
时直接返回。正常菜单切换仍会执行原有重排。

已通过精确设备程序集的 Harmony/补丁测试，并新增“标题菜单释放态不重入
布局资源”回归断言。新 DLL 已原子部署到设备：

```text
/mnt/sdcard/Ports/StardewVerticalWorldD2/StardewVerticalWorldD2/StardewValleyMainline/Mods/RGDSplus.VerticalWorld/VerticalWorld.dll
SHA256 330eede34cd8c3b252999b61215e3175603fd3ba198701ebaf7aa9a2add208e0
```

旧 DLL 已保留为同目录的
`VerticalWorld.dll.before-title-teardown-20261009-003121` 备份。
下次从 Card2 正常启动后，需重新验证 PC 主机加入、进入农场、移动和退出。

1. 从正式 Card2 入口启动掌机，在 PC 主机农场预留小屋并允许 IP 连接。
2. 掌机输入 PC 当前 IP，确认能进入农场而非仅建立网络连接。
3. 确认人物移动、工具使用、地图切换与双屏两种模式正常。
4. 再测试掌机主持、PC 加入。
5. 正常退出后查日志，确认没有新的联网或双屏异常。

在完成两方向实测前，不宣称“局域网完整支持已验收”。
