# 首用与帧间隔优化验收（2026-10-12）

## 范围和预先约定的门槛

基于 20261012-03 正式版；原分辨率、垂直同步、30 Hz 绘制目标和 60 Hz 逻辑更新保持。
只研究首次使用编译与显示提交节奏。测试静音、隔离配置、内存农场，不读写真实存档。

- 首用候选：至少三次新进程对照，覆盖砍树、割草、有效石块。以动作触发后两秒的最大帧为指标，
  同场景中位数至少改善 30%，其他工具不恶化超过 10%；优选目标 150 ms，未达到须明确记录。
  启动额外耗时不超过 5 秒，稳定内存增量不超过 20 MiB，无新增 OOM。
- 节奏候选：使用与缓冲 commit 对齐的 Wayland feedback。每个热场景至少三段 60 秒；
  三刷新及以上的间隔占比至少相对减少 30%，且其他场景不得增加超过 1 个百分点；
  平均呈现帧率不得降低超过 0.5 FPS。检查 discarded、提交覆盖率、显示序列和刷新周期。
  两个刷新周期约 33.2 ms；不能用绘制平均 FPS 代替显示端验收。
- 候选只各自过关才启用；两项无需捆绑发布。
- 入选方案连续 30 分钟，普通与密集场景、两种显示模式交替；按固定长度窗口记录，避免采样数组截断。
  无 OOM、无持续内存增长、无新增错误；像素和 UI/触控检查通过，正常返回标题和桌面。
- 诊断 JIT 事件追踪不用于正式性能验收；所有对照保持相同探针配置。
- 未过关保留正式方案，保留原始数据和失败结论，不为了交付而放宽门槛。

## 测量边界

内存农场不等于所有真实农场、天气和大型 MOD；Wayland feedback 只报告一个输出，不能冒充
两块屏幕独立的物理测试。最终仍需用户对体感确认，但自动验收先独立完成。

## 诊断与排除

数据根目录 `build/performance-followup-20261012/`。
`trace/` 中曾有两个诊断命令重叠，全部时序结果作废，不用于首用或帧节奏对照。
随后 `trace-clean-1/` 按顺序在新进程重跑，其 JIT 方法列表用于候选清单，但启用了运行时事件，
也不用于性能验收。`baseline-*`、`warmup-*` 才是关闭事件追踪的对照组。
早期 `build/performance-20261012-170855/` 使用历史 QA 驱动，只作问题复现，不与新矩阵混用。

候选清单依据首次砍树、割草和敲石的实际编译方法，以类型名和方法名匹配，
不会用易随游戏版本变化的元数据 token。包含首次工具绘制、掉落物更新和拾取路径；
不执行游戏动作来预热。设有时间和方法数量上限，缺失/不支持的方法不阻断启动。

正式候选 v2 补充了详细计时探针安装时提前编译的工具动作入口。最终三次验收使用
`SDV_PERF_TICK_ONLY=1`，只计时引擎 Tick、观察实际 Draw，并采集显示反馈；不预先补丁
工具、树木、草和石块方法。最终矩阵命名 `baseline-light-*` / `warmup-final-*`。
v1 的详细探针结果仅作筛选证据，不代替 v2 的正式验收。

## 三次新进程首用验收

对照按 baseline1→candidate1→candidate2→baseline2→baseline3→candidate3 交错执行。
各轮冷样本 20 秒、热样本 60 秒；均关闭 JIT 事件追踪及工具方法计时补丁。
下表为三次中位数，首用指标只取第一次动作触发后的两秒，不能代表整段最坏帧。

| 场景 | 原版首用最大帧 | 候选首用最大帧 | 原版热运行呈现 FPS | 候选热运行呈现 FPS |
| --- | ---: | ---: | ---: | ---: |
| 密集树木/斧头 | 641.18 ms | 53.81 ms | 29.16 | 29.18 |
| 混合植被/镰刀 | 518.70 ms | 38.51 ms | 30.00 | 30.01 |
| 有效石块/镐 | 206.14 ms | 42.28 ms | 30.00 | 30.00 |

三类改善分别约 91.6%、92.6%、79.5%，均超过 30% 门槛。197 个方法准备耗时
1997.38 / 1995.85 / 1996.57 ms，无准备失败；热运行 RSS 中位数差为 +3.66 / +0.64 / −0.51 MiB。
不同进程缓存和内存回收存在波动，不能把个别较低 RSS 解释为预热能节省内存。
完整门槛结果见 `build/performance-followup-20261012/warmup-final-evaluation.json`。

候选三轮完整冷样本仍出现最高 154.06 ms 的后续长帧，热样本最高 82.53 ms。
本次缩短的是已测三类工具的首次编译停顿，没有消除所有后续卡顿。

## 出帧节奏候选未入选

使用原版详细探针基线作有界筛选，各方案一轮、每个热场景 60 秒。
`wall` 用墙钟截止时间控制绘制，`wait` 另加等待以对齐截止时间；均保留垂直同步。
三刷新及以上呈现间隔占比（砍树 / 混合 / 石块）：

- 原方案：8.75% / 4.66% / 3.82%。
- wall：8.08% / 6.04% / 4.11%；混合场景反而增加超过 1 个百分点。
- wait：8.14% / 4.37% / 3.53%；改善不足 30%。

两者在筛选轮已不满足门槛，停止继续投入，没有把单轮结果当成通过三轮正式验收。
未修改正式 `FramePacing.cs`，候选仅存在 QA 插件。显示端的 50–66 ms 间隔仍需后续研究，
不能以平均 30 FPS 推断体感已稳。此结论只否定这两个实现，并非证明硬件上完全无法改善。

## 长时与兼容验收

已完成 30 个 60 秒窗口，总计测量 1809.08 秒，依次重复走动、混合植被、密树、稀疏场景、混合植被、石块；
每六个窗口切换屏幕模式。窗口间重建内存场景，游戏进程保持运行，非连续同一农场录制。
额外 UI 状态读取位于测量边界之外，用于核对 60 Hz 逻辑计数；三轮首用数据不受该读取影响。
候选正式 DLL SHA256：`f39b26ff3abbfc5f811e31ecb38f927ee55811a02b63fa9bab8c431d55d54cd1`。
所有窗口保留原分辨率、swap interval 1、30 帧绘制目标；逻辑计数 59.885–60.073 Hz。
显示反馈没有丢弃、重复时间或提交覆盖缺口；内核 `oom_kill` 2→2，无新增运行错误，
游戏退出码 0。像素核对通过，正式存档和配置 SHA256 一致。

但长测**不予放行**，不能把上述自动检查通过解释为完整验收成功：

- 第一次混合植被约 22.20 呈现 FPS，第一次密树仅 13.73；随后同类窗口恢复为约 30 / 29.1。
  补跑未修改的 20261012-03、相同行走与场景顺序后，混合植被同样约 21.73，
  但密树为 28.45。混合场景下降并非候选独有，候选首次密树下降仍无法解释，未通过无回退要求。
- 驻留内存从约 559 MiB 到 609 MiB，期间有回落但后半程仍有增长；托管内存约 121→235 MiB。
  反复重建内存场景可能影响数据，但尚未排除持续增长，不能宣称内存稳定。
- 第 30 窗口出现 527.52 ms 长帧和随后 182.13 ms 帧。该段 JIT 增量为 0，附近有 GC，
  不能仅凭相关性断定根因。首次走动仍有 190.81 ms 长帧（旧版同顺序约 200.52 ms）。

原始记录：`soak-1/`、`dense-control-1/`。`soak-1/evaluation.json` 将自动检查和最终发布许可分开，
`releaseApproved=false`。未进入候选邮件/触控/标题兼容测试及正式部署阶段，因为长测已不满足门槛。

## 本轮结论

**完成有界试验，不发布优化。设备继续使用 20261012-03。**
首用预编译值得保留继续研究：三个工具短测改善明确，启动代价约 2 秒。
但不能用首用成绩掩盖长测回退、残留半秒停顿或内存趋势。
两种节奏方案均未达到 30% 改善目标，正式节奏保持不变。

本地候选 `20261012-04` 曾通过 7 项打包检查，现移至
`build/performance-followup-20261012/rejected-release-20261012-04/`，不是正式发布包。
正式发布配置、版本号和本地发布 DLL 已恢复；实验源码仅在显式 `SDV_FIRST_USE_WARMUP=1` 时启用。
候选文件固定保留于 `candidates/VerticalWorld.warmup-v2.dll`，不会由正式入口启用。
下一步若继续，应先复现首个密树窗口的差异并解释内存增长，再决定是否扩大预热范围；本轮不再追加盲目调参。

## 最终清理

旧版同顺序对照完成 12 个一分钟窗口并正常退出。旧版托管内存也从约 120→167 MiB，
与候选前 12 窗口的 121→168 MiB 很接近，提示场景重建/探针本身可能贡献增长；
这仍不等于已证明候选 30 分钟后的内存稳定，故保留不放行结论。
旧版副屏密树后续长帧 178.46 ms，候选同类 175.20 ms；原有持续卡顿也需要独立处理。

`final-device-audit.json` 核对设备仍为 `20261012-03`，正式入口及 DLL 与发布清单哈希一致，
测试插件移除、无游戏进程、存档与配置未变、输出 `Mute: yes`。
最终双屏抓图 `final-system-upper.png` / `final-system-lower.png` 确认停在系统应用列表。
用户下次手动从正式入口启动时仍按原逻辑恢复声音。
