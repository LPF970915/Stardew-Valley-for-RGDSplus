# 双屏项目已验证经验交接文档

更新时间：2026-10-08

本文只记录已经在本机、设备或自动化流程中验证过的结论，供其他窗口继续维护时直接使用。没有把设计设想、未完成的标题动画或仅凭源码检查得到的结论写成“已通过”。

## 1. 最终入口与设备

- 掌机菜单入口：`Ports -> Stardew Valley Vertical World D2 Card2`
- 设备地址：`[device-host]`
- 设备实际游戏目录：`/mnt/sdcard/Ports/StardewVerticalWorldD2/StardewVerticalWorldD2/StardewValleyMainline`
- 入口脚本：`/mnt/sdcard/Ports/Stardew Valley Vertical World D2 Card2.sh`
- 设备平台：RGDSplus，两个实体屏均为 `1024x768`

正式使用必须从完整的 Card2 双屏入口启动。SSH/QA 启动只用于测试，不应被当作最终用户入口。

## 2. 不可破坏的显示架构

### 2.1 逻辑尺寸与物理尺寸必须分开

- 游戏逻辑、世界、碰撞、菜单、命中框和 HUD 仍使用单屏 `1024x768`。
- 双屏物理承载帧是横向 `2048x768`，只是 RGDSplus 的传输/合成格式。
- 不要把游戏全局窗口或 `Game1.screen` 改成 `1024x1536`，也不要把逻辑宽度改成 `2048`。
- 纵向连续世界只在渲染适配层通过两个 `1024x768` 视口实现。

### 2.2 已验证的物理映射

当前成功版本的映射是：

```text
共享帧 x=0..1023       -> 物理上屏
共享帧 x=1024..2047    -> 物理下屏
```

对应的 DRM 抓屏入口：

```sh
kmsgrab --crtc 130   # 上屏
kmsgrab --crtc 90    # 下屏
```

不要把代码中的 `left/right` 直接当成 `upper/lower` 命名；这里的“上屏/下屏”是物理语义。历史文档中存在早期相反映射，已被实机确认的当前映射取代。

### 2.3 世界相机经验

- 相机 X 必须依据玩家位置和地图宽度计算，不能固定为 0。
- 两个纵向视口使用相邻的 Y 区间；相机接近地图底部时才向下段移动。
- 不要用复制整帧、第二个游戏进程或第二次游戏更新循环模拟下屏。
- 世界视口临时改变后，绘制 HUD/菜单前必须恢复原生 `1024x768` UI 视口。

## 3. 两种已验证模式

### `SceneHud`：连续双屏默认态

- 上屏显示完整原生 4:3 世界和人物。
- 下屏显示同一世界的连续扩展区域，并叠加原生 HUD/工具栏。
- 保留原生 `Start` 暂停菜单。
- 世界和 UI 共用同一进程、同一更新循环、同一存档。

### `ExpandedHud`：单屏加副屏窗口态

- 上屏继续显示世界和对话。
- 下屏常驻自定义 4:3 页面，页面之间直接切换，不打开旧式暂停弹窗。
- `Start` 在此模式下被拦截；不能再次打开弹窗。
- `B`/返回关闭当前页面或详情，回到下屏目录/游玩态。
- 下屏页面打开时，上屏世界仍持续更新。

当前源码已进入 `0.6.0-reference-v2` 路径。早期本地 12 行左侧导航属于旧布局，并不等价于原模组 2.0；继续改下屏时先读 `docs/UPSTREAM_V2_LAYOUT_AUDIT.zh-CN.md`、`docs/REFERENCE_V2_UI.zh-CN.md` 和 `dualscreen/VerticalWorld/ReferencePages.cs`，不要从旧截图推断当前页面路由或美术结构。

模式切换使用实体 `Select`。D2 Card2 入口已兼容 `ControllerBack`、`Back` 和 `C` 回退输入；不要把 `Start` 当作模式切换键。

## 4. UI 缩放与像素布局

- 两种模式共享同一个 UI 缩放偏好。
- 默认 UI 缩放为 **150%**，以 4.3 英寸 `1024x768` 屏幕的可读性为准。
- UI 缩放与世界缩放相互独立；改变 UI 缩放不能改变世界相机。
- 用户明确设置其他比例后应保留该选择，不能在切换模式、重新进存档或新一天时强行重置为 150%。
- 背包、固定快捷栏和页面内物品必须以原生 `drawInMenu` 的 32 像素中心偏移定位；不能把缩放后的 64 像素格边长当作图标定位偏移。
- 数量/品质标记应在格子内部右下/左下绘制，避免出格。
- 状态栏中生命/体力文字放在对应条形图左侧，避免右上角数值超框。
- 下屏控件使用游戏自带像素资源、原生字体、原生橙色实心按钮和原始箭头/标签素材；不要用通用网页边框或自画符号替代已存在的游戏资源。

## 5. 已验证的输入行为

- 副屏触摸坐标统一归一化到本地 `1024x768`。
- 同时接受本地下屏坐标 `0..1023` 和共享窗口右半坐标 `1024..2047` 的映射。
- 触摸按下、移动、释放必须按完整 evdev 批次解析，不能只取一次 `read()` 的首事件。
- 下屏列表松手时确认点击；拖动不能误打开详情。
- 鼠标合成事件需要短暂抑制，避免一次触摸触发两次点击。
- 下屏页面支持纵向拖动和滚轮滚动；页面滚动状态按页面/子页分别保存。
- 关闭页面或切换模式后，必须等待旧按键/触点释放，不能让迟到的释放事件点击新页面。

## 6. QA 测试边界

自动化测试只有在显式设置 `SDV_DUAL_UI_TEST_DIR` 时才启用：

```text
SDV_DUAL_UI_TEST_DIR=/tmp/sdv-ui-qa
```

QA 环境使用内存 fixture 农场：

- 不读取用户真实存档。
- 不保存或迁移测试农场。
- 测试进程退出后 fixture 丢弃。
- 正常用户启动环境中不应出现 `SDV_DUAL_UI_TEST_DIR`。

设备 QA 入口示例（PowerShell）：

```powershell
$env:RGDSPLUS_SSH_PASSWORD = "<设备密码>"
python tools/qa-device-ui.py launch   # 仅启动 QA 内存环境
python tools/qa-reference-v2.py suite
python tools/qa-device-ui.py normal  # 无 QA 环境的正常启动检查
```

`normal` 用于无 QA 环境的正常启动检查。不要在用户正在手动游玩时直接执行会终止游戏进程的 QA 启动流程；部署或重启前先让用户保存并退出。

## 7. 实体双屏可见验证

QA 截图不能替代实体屏幕验证。完整可见轮播使用真实 Card2 双屏入口和 DRM 两路抓屏：

```powershell
$env:RGDSPLUS_SSH_PASSWORD = "<设备密码>"
python tools/qa-visible-showcase.py --hold 1
```

该流程已验证：

- 中文、英文。
- 150%、125%、100%、75%。
- 12 个下屏页面。
- 每页约 1 秒展示。
- 共 `96/96` 组合通过。
- 每组同时保存上屏、下屏和 `1024x1536` 纵向拼接参考图。

产物目录：`build/acceptance-visible-ui/`，结果文件：`build/acceptance-visible-ui/results.json`。

脚本中的物理抓屏必须保持：

```python
((130, "upper"), (90, "lower"))
```

如果只看到下屏而上屏仍停留在系统菜单，优先检查窗口定位，而不是先改渲染代码。曾经出现过窗口被放到 `X=1024`，导致只有一块屏显示；修正 QA 窗口定位元数据后，两屏实体输出恢复正常。

## 8. 已验证的稳定性修复

### 8.1 纹理自赋值导致的黑帧/频闪

`Game1.screen` 和 `Game1.uiScreen` 的 setter 会释放旧对象。不能把同一个纹理引用再次赋回去；只有目标引用真正变化时才允许赋值。否则会出现下屏交替黑帧、纹理每帧重建或菜单频闪。

### 8.2 花瓣/天气粒子跨屏抖动

天气粒子必须按统一的世界/屏幕坐标裁剪和合成，不能让粒子在上下屏边界重复提交或在下屏顶部累积。已修复花瓣在上屏抖动闪烁、下屏顶部堆积并持续闪烁的问题；部署后用户手动观察到花瓣恢复正常降落。

### 8.3 标题/加载态回退

标题、加载和没有调用世界绘制的状态不能把两个空目标直接合成为黑屏。应让原生呈现路径接管，只有世界绘制有效时才使用双屏世界合成。

## 9. 部署和回退原则

- 只修改实际被入口选中的嵌套运行目录；不能仅凭外层目录名判断 gamedata 所在位置。
- 卡二文件系统不依赖符号链接；入口保留目录探测逻辑。
- 部署前先备份设备端 DLL、入口和配置。
- 使用 `.next` 临时文件上传，校验哈希后再 `mv` 原子替换。
- 不强制结束用户手工测试；新 DLL 等待下次正常退出并重新从 Card2 入口启动后才生效。
- 不覆盖真实游戏资源、Steam 凭据、`savedata/Saves/` 或 QA 日志。
- 新增 `port/` 顶层文件时，必须同步检查 `tools/make-card2-package.ps1` 或对应 Card2 打包脚本，因为该脚本不是复制整个 `port/` 目录。

## 11. 其他窗口接手清单

1. 先读本文、Reference v2 验收和原模组布局审计，不要按早期实验映射工作。
2. 确认入口仍为 `Stardew Valley Vertical World D2 Card2`，确认设备端没有遗留 `SDV_DUAL_UI_TEST_DIR`。
3. 修改渲染前先保持 `2048x768` 物理承载、`1024x768` 游戏逻辑和当前上/下屏映射不变。
4. UI 修改默认以 150% 检查，并至少验证背包图标、固定快捷栏、状态栏和触摸命中框。
5. 自动化只使用 QA 内存农场；真实存档操作必须先明确范围并获得授权。
6. 代码检查通过后，至少运行一次 `qa-visible-showcase.py --hold 1`，确认实体两屏都在变化。
7. 部署只做备份、哈希校验、原子替换；等待用户正常重启后再宣称设备加载新版本。
