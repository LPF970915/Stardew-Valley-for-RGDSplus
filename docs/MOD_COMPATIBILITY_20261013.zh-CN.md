# MOD 兼容层修复与加载提示（20261013-05）

修复全部随发布包提供，不写回 Steam 资源、用户 MOD 文件或存档。

- 启动器只读扫描 `Mods`，将启用项复制到 `.rgds-runtime/Mods`，由 SMAPI 加载副本。
- 处理 `OO.Portraits`、`OO.Portraits2`、`Mud.SkimpyPortraits`、`Mud.SkimpyPortraits2` 的肖像资源。`Portrait` / `Portraits` 文件夹下，边长达到 512 的 PNG 生成 1/8 常驻图；行走精灵、ScaleUp 人物贴图和其他资源保持原尺寸。
- 运行副本同步换算 DDF 表情分格与能精确映射的 Content Patcher `FromArea`。单幅 600×600 图也处理，防止把头像的一小块误当成整幅。
- 实际对话按像素指纹识别当前肖像资源，仅从原 PNG 流式读取当前表情。600×600 表情保留原分辨率；较大表情作 1/2 采样（例如 1000×1800 → 500×900）。内存只保留当前一张高清纹理，关闭对话后释放；磁盘副本留在私有缓存中。
- 图片解码只保留少量扫描行，既不把整个高清表情图集解码进内存，也不修改原图。首次显示某个表情需要短暂解码，之后直接复用私有磁盘缓存。
- DDF 通过可选 Harmony 适配，不替换第三方 DLL。布局按当前视口分配立绘、姓名、好感度和文字区域，保持立绘宽高比。长文本按实际区域分页；对话中调整 UI 缩放会重新分页剩余文字。
- 修正原生 DialogueBox 与旧对话路由重复绘制；构造和尺寸变化的最终边界钳制在 DDF 修改后执行。
- 高清表情先从原 PNG 面积预滤波到适合当前设备的临时纹理，再用原有点采样绘制；不在 SpriteBatch.Draw 回调中切换批次状态。
- 启动器和双屏界面显示启动、MOD 兼容准备及 SMAPI 实际新建/读档加载阶段；异常退出记录内存、OOM/段错误和 SMAPI 日志线索。
- 上次报告的闪退没有留下可读堆栈或内核 OOM 记录，因此无法确认是具体哪个 MOD 或内存峰值导致；本版降低渲染批次风险并增加可诊断性，尚未实机复测。
- 约 1 GiB 设备默认将此游戏的 .NET 托管堆预算限制为 256 MiB，给固件与图形驱动留空间；可通过现有同名环境变量覆盖。
- MOD 开关写入 `.rgds-runtime/mod-state.json`，退出到桌面后重启生效。坏 manifest 单独跳过，列表显示扫描提示；来源目录与本次实际加载目录分开读取。
- 旧版隐藏的原始目录在原处读取；旧生成的 `RGDSplus.ModCompatibility--*` 替换包被忽略。只有能匹配旧兼容替换包的指定肖像原包默认恢复启用，普通手动禁用项保持关闭。
- 私有运行目录的配置、数据和本模组历史记录在重建/开关后保留，运行日志与配置写入不会强迫重新缩图。肖像转换结果另有缓存，修改开关无需再次解码全部原图。

SVE 肖像包不包含 SVE 角色本身，需要另行安装其对应内容与前置。针对其他大型 MOD 的全部功能，不能仅凭肖像兼容测试推断可用。

实机测试及文件保护校验记录位于工作区 `build/mod-device-20261013`。最终验收结果在该目录的报告中记录。
